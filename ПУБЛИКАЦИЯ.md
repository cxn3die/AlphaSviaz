# Публикация сайта

## GitHub Pages — автоматически

Всё настроено: после каждого `git push` в ветку `main` GitHub сам соберёт
сайт и обновит его. Вручную ничего собирать и перетаскивать не нужно.

### Что сделать один раз

1. Завести аккаунт на [github.com](https://github.com) (бесплатно).
2. Создать пустой репозиторий: **New repository**. Имя любое, например
   `alfa-svyaz`. **Не** добавлять README, .gitignore и лицензию —
   репозиторий должен быть пустым.
3. В папке проекта выполнить (подставьте свой логин и имя репозитория):

   ```
   git remote add origin https://github.com/ЛОГИН/alfa-svyaz.git
   git push -u origin main
   ```

4. В репозитории: **Settings** → **Pages** → в поле **Source** выбрать
   **GitHub Actions**.
5. Открыть вкладку **Actions** — там пойдёт сборка. Через пару минут сайт
   будет по адресу `https://ЛОГИН.github.io/alfa-svyaz/`.

Дальше любое изменение публикуется так:

```
git add -A
git commit -m "что поменяли"
git push
```

### Адрес сайта

| Имя репозитория | Адрес |
|---|---|
| `alfa-svyaz` (любое) | `https://ЛОГИН.github.io/alfa-svyaz/` |
| `ЛОГИН.github.io` | `https://ЛОГИН.github.io/` — без подпапки |

Префикс подставляется при сборке сам, менять ничего не нужно.

### Свой домен

**Settings** → **Pages** → **Custom domain**. После привязки домена сайт
отдаётся из корня, и префикс в сборке нужно отключить: добавьте в
репозитории **Settings** → **Secrets and variables** → **Actions** →
вкладка **Variables** переменную `NEXT_PUBLIC_BASE_PATH` с пустым
значением, либо скажите мне — поправлю workflow.

## Что было настроено под GitHub Pages

Три вещи, без которых сайт на Pages открывается сломанным:

**Префикс пути.** Pages отдаёт проект по адресу `/<имя-репозитория>/`.
Все ссылки вида `/images/...` без префикса ушли бы в корень домена и
отдали 404. Workflow вычисляет префикс из имени репозитория и передаёт
его в сборку через `NEXT_PUBLIC_BASE_PATH`.

**Обёртка `AppImage`.** `next/image` с `unoptimized: true` отдаёт путь
как есть и префикс не подставляет. Обёртка
[components/ui/app-image.tsx](components/ui/app-image.tsx) делает это в
одном месте — в компонентах пути остаются обычными.

**Файл `.nojekyll`.** Pages прогоняет статику через Jekyll, а тот
пропускает папки с подчёркиванием — то есть весь `_next` со стилями и
скриптами. Пустой файл-маркер это отключает.

Ещё включён `trailingSlash` — страницы собираются как `about/index.html`
вместо `about.html`, такие адреса Pages отдаёт без сюрпризов.

## Ручная сборка — для Netlify или Cloudflare Pages

```
npm run build
```

Готовый сайт появится в папке `out` — её и загружают.

**Netlify:** заливать только из аккаунта. Анонимный деплой через
Netlify Drop живёт один час и удаляется.

**Cloudflare Pages:** Workers & Pages → Create → Pages → Upload assets.
Трафик не лимитирован.

## Локальный запуск

```
npm install
npm run dev
```

Откроется на `http://localhost:3000`.
